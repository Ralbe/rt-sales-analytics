# Аналитика продаж

Веб-приложение для учёта коммерческих проектов: карточки, помесячные суммы, история изменений, реестр и дашборды. Вход — по паролю и коду из TOTP-аутентификатора.

## Быстрый старт (Docker)

```bash
cp .env.example .env
docker compose up --build -d
```

Откройте [приложение](http://localhost:8080). Документация API: [Swagger](http://localhost:8080/api/docs). Остановить сервисы можно командой `docker compose stop`; данные останутся в томе PostgreSQL.

Мониторинг (Prometheus + Grafana): `docker compose --profile monitoring up -d`, Grafana: http://localhost:3001.

### Трассировка запросов (опционально)

API поддерживает экспорт HTTP-трасс через OTLP/HTTP. По умолчанию экспорт выключен, поэтому для обычного запуска Collector не нужен. Чтобы включить экспорт, укажите в `.env`:

```dotenv
OTEL_TRACES_EXPORTER=otlp
OTEL_TRACES_SAMPLER=parentbased_traceidratio
OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4318
OTEL_SERVICE_NAME=rt-analytics-api
OTEL_TRACES_SAMPLER_ARG=1.0
```

Имя `otel-collector` замените на адрес Collector, доступный из контейнера API. В Collector трассы принимаются по адресу `/v1/traces`. Доля семплирования задаётся значением от `0.0` до `1.0`; `1.0` сохраняет все корневые трассы. Для дочерних трасс решение о семплировании наследуется из входящего `traceparent`. Prometheus-метрики остаются отдельным каналом.

HTTP-трассы содержат метод, шаблон маршрута и код ответа. Query-параметры, заголовки, cookies, тела запросов и ответов, идентификаторы пользователей и тексты исключений не добавляются. Маршруты health-check, метрик и документации исключены. Трассировка охватывает HTTP-запросы API; Celery и SQL-запросы не инструментируются.

### Демо-пользователи

Пароль у всех: `Demo2026!` (только для демо, задаётся в `backend/app/seed.py`).

| Email | Роль | Что может |
|---|---|---|
| analyst@example.com | Аналитик | Просмотр и редактирование всех проектов, настройка и публикация дашбордов |
| head@example.com | Администратор | Управление пользователями, подписями полей и архивом проектов |
| manager1@example.com | Пользователь | Только свои проекты, создание и редактирование |
| admin@example.com | Администратор | Управление пользователями, подписями полей и архивом проектов |

При первом входе показывается QR-код — его нужно отсканировать в приложении-аутентификаторе (Яндекс Ключ, Google Authenticator и др.), затем ввести 6-значный код.

### Управление пользователями

Администратору доступен раздел «Пользователи»: поиск, создание учётной записи, изменение ФИО, email, роли и активности. При создании задаётся пароль; первый вход нового пользователя требует настройки 2FA. После отключения учётной записи её текущие сессии сразу теряют доступ. Повторное включение требует нового входа с паролем и 2FA: прежние сессии и начатые попытки входа остаются недействительными, настройка TOTP сохраняется.

Собственную учётную запись отключить нельзя. Последний активный администратор не может лишиться административной роли. Изменения записываются в журнал без паролей, хешей и секретов 2FA. Аналитик и обычный пользователь не имеют доступа к административному API.

## Возможности

- Карточки проектов с проверкой полей, поиском клиента по названию или ИНН и сохранением черновика.
- Помесячные строки выручки и затрат. Карточка, финансовые строки и аудит сохраняются одной транзакцией.
- Реестр с поиском, фильтрами, сортировкой и выгрузкой в XLSX. После входа открывается реестр.
- Последние десять изменений в карточке: автор, дата и значения до и после правки.
- Архивирование и восстановление проектов администратором с сохранением финансов и истории.
- Настройка подписей полей. Текущие экраны используют новые названия, история сохраняет прежние.
- Дашборды с графиками, таблицами и прогнозом. Аналитик или администратор может настроить свои виджеты и открыть дашборд для просмотра другим пользователям.

Старые проекты сохраняют шесть прежних стадий. Для нового проекта нужно выбрать один из десяти этапов заказчика; вероятность подставляет сервер. У старых проектов процент меняется вручную. Автоматического переноса между моделями нет, правила завершения новых проектов пока не определены.

Сумма договора и себестоимость карточки указываются в рублях, месячные строки — в тысячах рублей. В месячных строках сохраняются введённая сумма и признак «с НДС / без НДС»; пересчёта нет. Год реализации — одно целое число; статус, сделанное и планы — до 1000 символов каждый.

В XLSX дата создания выводится текстом ISO 8601 в UTC; значения из пользовательских полей остаются текстом и не исполняются как формулы.

## Архитектура

```
Браузер ──► Nginx ─┬─► Next.js (React, TypeScript)       /
                   └─► FastAPI (Python 3.12, Pydantic)   /api
                          ├─ PostgreSQL (SQLAlchemy 2.0, Alembic)
                          ├─ Redis — кэш аналитики, лимит попыток входа
                          └─ RabbitMQ ─► Celery worker + beat — прогрев кэша
Prometheus ◄── /metrics ── FastAPI;  Grafana ◄── Prometheus
```

- **Аналитика** на Pandas и фильтр открытых проектов сейчас учитывают только проекты с шестью прежними стадиями. Проекты с новыми этапами в эти показатели не входят. Полного восстановления прошлых значений из аудита пока нет.
- **Кэш**: результаты аналитики лежат в Redis 5 минут; любое изменение проекта сразу сбрасывает кэш. Без Redis приложение работает, просто без кэша.
- **Права**: пользователь видит и меняет только свои проекты; аналитик и администратор работают со всеми проектами. Администратор также управляет пользователями, подписями полей и архивом. Чужие закрытые дашборды остаются приватными.
- **Журнал действий**: входы, создание и изменение проектов, клиентов и дашбордов пишутся в таблицу `audit_log`. В карточке проекта показаны последние 10 событий: автор, дата, изменённые поля и значения до/после, включая финансовые строки. История доступна только вместе с самим проектом. Для старых неполных записей отсутствие значения обозначается явно; новые события сохраняют названия справочников на момент изменения.

## PDF и печать

В сохранённой карточке нажмите «PDF / Печать карточки». В печать попадут сохранённые данные, включая помесячные суммы и признак НДС. Несохранённые правки формы в этот снимок не входят.

Откройте дашборд, дождитесь загрузки показателей и нажмите «PDF / Печать». В диалоге браузера выберите «Сохранить как PDF» и формат A4. Отчёт содержит название, время формирования, текущие фильтры и виджеты с их периодами. Несохранённые изменения редактора также входят в снимок; экспорт не сохраняет их в базе.

Печатная версия строится из уже загруженных данных, включает графики в SVG и таблицы без экранной прокрутки. Пока данные загружаются или содержат ошибку, печать недоступна. Данные не отправляются во внешние сервисы.

## Локальная разработка без Docker

Пример для bash. В PowerShell активация окружения — `.venv\Scripts\Activate.ps1`, переменные среды задаются через `$env:DATABASE_URL` и `$env:REDIS_URL`.

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
# нужен PostgreSQL; для быстрой пробы можно SQLite:
export DATABASE_URL=sqlite:///dev.db REDIS_URL=
alembic upgrade head && python -m app.seed
uvicorn app.main:app --reload --port 8000
```

```bash
cd frontend
npm ci
npm run dev     # http://localhost:3000, /api проксируется на 127.0.0.1:8000
```

На SQLite поиск без учёта регистра не работает для кириллицы. В PostgreSQL всё работает.

## Тесты и проверки

```bash
(cd backend && pytest -q && ruff check app tests)
(cd frontend && npm run typecheck && npm run lint && npm run build)
```

CI (`.github/workflows/ci.yml`) прогоняет тесты, применяет миграции на PostgreSQL и собирает Docker-образы.

## Границы текущей версии

Пока нет табличного конструктора и витрины отчётов, Ганта, расчёта длительностей этапов, автоматических индикаторов за период и редактора закрытых справочников. Новые финансовые расчёты и проверка ALT Linux отложены. Совместимость выгрузок с Excel, LibreOffice и МойОфис отдельно не проверялась.

XLSX реестра ограничен первыми 10 000 проектами выборки; предупреждение о превышении пока не выводится.
