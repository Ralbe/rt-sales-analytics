## Как повторить

Для сервера установите `backend/requirements-dev.txt`. В каталоге `backend`:

```powershell
$env:TEST_POSTGRES_URL = 'postgresql+psycopg://USER:PASSWORD@localhost:5432/TEST_DATABASE'
python -m ruff check app tests
python -m pytest -q
```

Укажите отдельный тестовый PostgreSQL. Проверки PostgreSQL создают временные базы; пользователю нужны права на их создание. Без `TEST_POSTGRES_URL` эта часть набора пропускается.

В каталоге `frontend`:

```powershell
npm ci
npm run typecheck
npm run lint
npm run build
npx playwright install chromium
npx playwright test --config=playwright.mock.config.ts
```

Для четырёх сценариев `playwright.live.config.ts` дополнительно нужны работающий API, отдельная заполненная тестовая база, переменные `E2E_EMAIL`, `E2E_PASSWORD`, `E2E_TOTP_SECRET` и Python с серверными зависимостями в PATH. Адрес API задаётся через `BACKEND_URL` **перед сборкой** интерфейса. В `.github/workflows/ci.yml` сохранён полный порядок подготовки и запуска всех проверок в Linux.

## Границы проверки

Автоматические проверки не заменяют приёмку бизнес-правил командой. Распределение суммы контракта именно по этапам пока требует уточнения; в этой версии улучшен помесячный ввод. Правила прибыли, НДС, последнего месяца выручки и статистики описаны в `changes-vika.md`.

Нагрузочная проверка на производственном объёме данных, внешние источники кроме XLSX и совместимость с МойОфис не проверялись. Проверка ALT Linux исключена из согласованного объёма.

В серверном прогоне остались предупреждения библиотек об устаревающих API и коротких ключах из тестовых фикстур; ошибок тестов нет. Для рабочей установки задаётся собственный длинный `SECRET_KEY`, как указано в инструкции запуска.

После исправления масштаба повторно прошла 21 проверка дашборда и печати, включая заполнение высоты окна в режимах 90%, 100%, 115% и 130%. Режим «Мелкий» также проверен по снимку экрана.
